# SmartRoom

ระบบจองห้องติวหนังสือในมหาวิทยาลัย แสดงสถานะห้องจากการจองและการเช็กอินจริง

## เทคโนโลยี

- Bun + TypeScript (strict)
- Neon Postgres สำหรับเก็บข้อมูลถาวร
- Vercel Functions สำหรับ REST API
- Frontend TypeScript แบบไม่ใช้ framework
- ใช้ polling อัปเดตสถานะห้องและคิวทุก 10 วินาที

## รันในเครื่อง

1. โหมด `bun run dev` ใช้ข้อมูลเดโมในหน่วยความจำ ไม่แตะฐานข้อมูลจริง หากต้องการต่อ Neon ในเครื่องให้ใช้ `bun run dev:database`
2. สร้างฐานข้อมูล Postgres ใน Neon และคัดลอก connection string
3. สร้างไฟล์ `.env` โดยใส่:

   ```text
   DATABASE_URL=postgresql://...
   ADMIN_PASSWORD=รหัสผ่านแอดมิน
   ADMIN_SESSION_SECRET=สุ่มค่าอย่างน้อย 32 ตัวอักษร
   ```

4. รันคำสั่ง:

   ```bash
   bun install
   bun run dev:database
   ```

5. เปิด `http://localhost:3000` และหน้าแอดมินที่ `/admin`

โหมดเดโมไม่เชื่อมฐานข้อมูล แต่ต้องตั้งค่า `ADMIN_PASSWORD` และ `ADMIN_SESSION_SECRET` ใน `.env` หรือ `.env.local` เพื่อเข้าสู่ระบบแอดมิน เซิร์ฟเวอร์เดโมในเครื่องผูกไว้กับเครื่องนี้เท่านั้น หากต้องการทดสอบระบบแอดมินที่บันทึกลง Neon ให้ใช้ `bun run dev:database` หลังตั้งค่าตัวแปรด้านบน

การตั้งค่า Vercel ในโปรเจกต์นี้ใช้ฐานข้อมูล (`SMARTROOM_LOCAL_DEMO=false` ใน `vercel.json`) ส่วนโหมดเดโมในเครื่องเก็บข้อมูลในหน่วยความจำและไม่เหมาะกับการจองจริง

Schema จะถูกสร้างหรือปรับปรุงเมื่อมีการเรียก API ครั้งแรก รวมถึงตารางคิวรอห้อง โดยไม่มีการเติมห้องหรือประวัติตัวอย่างอัตโนมัติ หากฐานข้อมูลยังไม่มีห้อง ให้เพิ่มห้องผ่านระบบจัดการ

การทดสอบ PostgreSQL ใน `tests/waitlist-postgres.test.ts` ปิดไว้ตามค่าเริ่มต้น หากต้องการรัน ให้ใช้ Neon branch สำหรับทดสอบที่ทิ้งได้เท่านั้น ตั้ง `DATABASE_URL` ให้ชี้ branch นั้น แล้วตั้ง `SMARTROOM_TEST_POSTGRES=true` และ `SMARTROOM_TEST_NEON_BRANCH_ID` เป็น branch ID ที่ตรงกันก่อนรัน `bun test --env-file=.env.local` โดยการทดสอบอาจปรับ schema ห้ามใช้ฐานข้อมูล production

## Deploy ด้วย GitHub และ Vercel

1. Push โค้ดขึ้น GitHub โดยอย่า push ไฟล์ `.env` หรือ connection string
2. สร้างโปรเจกต์ฐานข้อมูลบน Neon และคัดลอก `DATABASE_URL` สำรองข้อมูลและตรวจสอบห้อง การจอง และคิวก่อนสลับจากระบบเดิม ข้อมูลในหน่วยความจำของเดโมจะไม่ย้ายไปโดยอัตโนมัติ
3. ใน Vercel เลือก **Add New Project** และ Import repository จาก GitHub
4. ใน Project Settings → Environment Variables ตั้ง `ADMIN_PASSWORD` เป็นรหัสผ่านที่คาดเดายาก และ `ADMIN_SESSION_SECRET` เป็นค่าสุ่มอย่างน้อย 32 ตัวอักษร สำหรับ Production (และ Preview หากต้องการ) หากใช้ฐานข้อมูลจริงให้เพิ่ม `DATABASE_URL` ด้วย อย่าเก็บค่าจริงในโค้ดหรือส่งเข้า Git
5. Deploy โปรเจกต์ Vercel จะรัน `bun run build` เพื่อสร้างไฟล์ frontend และ bundle API handler สำหรับ Function
6. เปิด URL ที่ Vercel ให้มา

เว็บผู้ใช้และระบบจัดการอยู่ใน Vercel โปรเจกต์เดียวกัน: หน้าเว็บผู้ใช้ที่ `/` และระบบจัดการที่ `/admin` ทั้งสองโหมดต้องใช้รหัสผ่านเข้าสู่ระบบแอดมิน โดยใช้ session cookie แบบ HttpOnly/SameSite และ API จัดการห้องตรวจ session ทุกครั้ง หากไม่ได้ตั้งค่า admin environment variables จะยังเข้าสู่ระบบจัดการไม่ได้ การเปลี่ยนรหัสผ่านจะทำให้ session เดิมใช้ไม่ได้

Vercel Functions ไม่เปิด WebSocket ค้างไว้ แอปจึง polling สถานะล่าสุดทุก 10 วินาที และหน้าเช็กอินมี SSE สำรองสำหรับข้อมูลการจองนั้น
การหมดเวลา เช็กอิน และข้อเสนอคิวจะถูกประมวลผลเมื่อมีการเรียก API ครั้งถัดไป

## คิวรอห้องและการต่อเวลา

- เมื่อห้องไม่ว่าง ผู้ใช้ระบุชื่อและระยะเวลา 30/60/120 นาทีเพื่อเข้าคิว ห้องจะเสนอให้ผู้ใช้ที่อยู่คิวแรกก่อน
- ข้อเสนอมีเวลา 5 นาที หากข้ามหรือหมดเวลา ระบบปล่อยข้อเสนอและส่งต่อคนถัดไป
- คิวผูกกับ ID แบบไม่ระบุตัวตนที่เก็บในเบราว์เซอร์เครื่องนั้น ไม่มีการยืนยันตัวบุคคลหรือบัญชีผู้ใช้ การล้างข้อมูลเว็บ/เปลี่ยนอุปกรณ์อาจทำให้เรียกคืนคิวไม่ได้
- ก่อนหมดเวลาใช้งาน 10 นาที ระบบถามว่ายังใช้ห้องอยู่หรือไม่ ต่อได้ครั้งละ 30 นาทีเมื่อไม่มีผู้รอคิว
- ผู้ใช้กดออกจากห้องก่อนเวลาได้ เพื่อส่งข้อเสนอให้คิวถัดไปทันที
- ผู้ใช้จัดการรายการและดูประวัติการจอง/คิวได้จากแท็บ “การจองของฉัน”
- ผู้ใช้มีการจองที่ยังไม่จบได้ครั้งละหนึ่งรายการ; ไม่มาเช็กอินครบ 3 ครั้งใน 30 วันจะพักสิทธิ์จอง 24 ชั่วโมง
- แอดมินเพิ่ม/แก้ไข/ปิดห้องและตั้งช่วงปิดปรับปรุงได้; คิวจะได้รับข้อเสนอหลังการจองที่มีอยู่สิ้นสุดและห้องเปิดใช้งาน

## คำสั่ง

```bash
bun run build      # สร้าง frontend ลง public/ และ bundle API handler
bun run dev        # build และเปิด server สำหรับพัฒนา
bun run start      # build และเปิด server
bun run typecheck  # ตรวจ TypeScript
```
